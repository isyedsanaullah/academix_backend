#### 11A: Exam Operations & Moderation (N25, N26, N27, N28)

##### 1. N25 Exam Seating Plan & Invigilation Roster (Standard Tier)
* **Institutional Job:** Automates examination hall desk assignments, ensuring students from the same section/class never sit adjacent to each other (preventing cheating during term/send-up exams), and generates teacher invigilation duty rosters.
* **Data Models:**
  ```prisma
  model ExamHall {
    id          String   @id @default(uuid())
    college_id  String
    campus_id   String?
    name        String   // "Jinnah Hall", "Room 102"
    capacity    Int
    rows        Int      // Grid rows
    columns     Int      // Grid columns
    isActive    Boolean  @default(true)
    createdAt   DateTime @default(now())
    updatedAt   DateTime @updatedAt

    desks       ExamHallDesk[]
    @@unique([college_id, name])
    @@index([college_id, isActive])
  }

  model ExamHallDesk {
    id        String   @id @default(uuid())
    hallId    String
    rowNum    Int
    colNum    Int
    deskCode  String   // e.g. "JH-R1-C1"
    hall      ExamHall @relation(fields: [hallId], references: [id], onDelete: Cascade)

    @@unique([hallId, rowNum, colNum])
  }

  model ExamSeatingPlan {
    id          String   @id @default(uuid())
    college_id  String
    campus_id   String?
    examId      String   // Links to existing Exam model
    name        String   // "Send-up Exam 2026 Seating Master"
    status      String   @default("DRAFT") // DRAFT | PUBLISHED | ARCHIVED
    generatedAt DateTime @default(now())

    seats       ExamAssignedSeat[]
    invigilators ExamInvigilationDuty[]
    @@unique([college_id, examId, name])
  }

  model ExamAssignedSeat {
    id            String   @id @default(uuid())
    seatingPlanId String
    deskId        String
    student_id    String
    examDate      DateTime @db.Date
    sessionTime   String   // MORNING | EVENING

    seatingPlan   ExamSeatingPlan @relation(fields: [seatingPlanId], references: [id], onDelete: Cascade)
    @@unique([seatingPlanId, deskId, examDate, sessionTime])
    @@unique([seatingPlanId, student_id, examDate, sessionTime])
    @@index([student_id])
  }

  model ExamInvigilationDuty {
    id            String   @id @default(uuid())
    seatingPlanId String
    teacher_id    String
    hallId        String
    dutyDate      DateTime @db.Date
    sessionTime   String   // MORNING | EVENING
    status        String   @default("ASSIGNED") // ASSIGNED | CONFIRMED | SUBSTITUTED

    seatingPlan   ExamSeatingPlan @relation(fields: [seatingPlanId], references: [id], onDelete: Cascade)
    @@unique([seatingPlanId, teacher_id, dutyDate, sessionTime])
    @@index([teacher_id, dutyDate])
  }
  ```
* **Seating Plan Solver Algorithm:**
  - Evaluates registered exam candidates grouped by `(class, section)`.
  - Alternates candidate rows across rooms: adjacent horizontal and vertical desks (`[r, c±1]`, `[r±1, c]`) must never be occupied by candidates of the same section or same subject paper.
  - Invigilation assignment verifies teacher duty caps (`maxInvigilationsPerWeek` from settings) and flags leave clashes against #63 staff leaves.
* **APIs:**
  - `POST /api/exams/halls`: Configure exam hall desk layout.
  - `POST /api/exams/seating-plan/generate`: Runs seating solver for specified `examId`, date, and hall list.
  - `GET /api/exams/seating-plan/:id/export-slips`: Generates printable hall desk slips and student exam entry permits (PDF via category `REPORTS`, exempt from storage quota).
  - `GET /api/exams/invigilation-roster`: Teacher view of invigilation schedule.

##### 2. N26 Paper-Setting & Moderation Workflow (Premium Tier)
* **Institutional Job:** Secure, multi-tier submission, peer review, and principal final seal for midterm, send-up, and mock examination question papers.
* **Data Models:**
  ```prisma
  model QuestionPaperDraft {
    id           String   @id @default(uuid())
    college_id   String
    campus_id    String?
    examId       String
    subject_id   String
    class        String
    setterId     String   // Teacher userId
    file_id      String   // StoredFile reference (encrypted/confidential)
    status       String   @default("DRAFT") // DRAFT | SUBMITTED | MODERATED | APPROVED | REJECTED | SEALED
    version      Int      @default(1)
    moderatorId  String?  // Head of Department / peer teacher
    moderatorNote String?
    sealedBy     String?  // Principal / Controller of Exams
    sealedAt     DateTime?
    createdAt    DateTime @default(now())
    updatedAt    DateTime @updatedAt

    revisions    QuestionPaperRevision[]
    @@index([college_id, examId, subject_id])
  }

  model QuestionPaperRevision {
    id           String   @id @default(uuid())
    paperDraftId String
    version      Int
    file_id      String
    uploadedById String
    changeNotes  String?
    createdAt    DateTime @default(now())

    draft        QuestionPaperDraft @relation(fields: [paperDraftId], references: [id], onDelete: Cascade)
    @@unique([paperDraftId, version])
  }
  ```
* **Security & Invariants:**
  - Question paper documents are stored in storage category `EXAM_PAPERS` with AES-256-GCM server-side encryption and restricted presigned download URLs (2-minute TTL).
  - Only assigned setter, designated moderator, and principal can access draft files before the exam date.
  - Paper setter cannot act as moderator for their own paper (`setterId !== moderatorId`).
  - Sealed papers cannot be deleted or re-uploaded without a Super Admin audit override.

##### 3. N27 Result Moderation & Student Re-Check Requests (Premium Tier)
* **Institutional Job:** Formal post-result recount and moderation portal allowing students/parents to submit re-check tickets, tracking recounting committees, and recording mark adjustments with audit trails.
* **Data Models:**
  ```prisma
  model ResultRecheckRequest {
    id              String    @id @default(uuid())
    college_id      String
    campus_id       String?
    student_id      String
    resultId        String    // References existing Result.id
    subject_id      String
    reason          String
    feePaidPkr      Int       @default(500)
    feeVoucherId    String?   // Linked fee challan for re-checking fee
    status          String    @default("SUBMITTED") // SUBMITTED | IN_REVIEW | RESOLVED_UNCHANGED | RESOLVED_CHANGED | REJECTED
    originalMarks   Decimal   @db.Decimal(5, 2)
    revisedMarks    Decimal?  @db.Decimal(5, 2)
    committeeNotes  String?
    reviewedBy      String?
    resolvedAt      DateTime?
    createdAt       DateTime  @default(now())
    updatedAt       DateTime  @updatedAt

    @@unique([college_id, resultId, subject_id])
    @@index([college_id, status])
  }
  ```
* **Integration with N11 Approvals:**
  - Any mark revision (`revisedMarks !== originalMarks`) automatically triggers an `ApprovalRequest(workflowType = 'MARKS_EDIT')`.
  - Result score in `Result` table is updated **only upon final step approval** of the approval chain.

##### 4. N28 Digital Report Card with Teacher Remarks (Standard Tier)
* **Institutional Job:** Comprehensive intermediate terminal progress card combining marks, class position, attendance percentage, psychomotor/affective domain ratings, and personalized qualitative remarks from section class teachers.
* **Data Models:**
  ```prisma
  model StudentReportCardRemark {
    id              String   @id @default(uuid())
    college_id      String
    campus_id       String?
    student_id      String
    session_id      String
    examId          String
    classTeacherId  String
    remarks         String   // Qualitative text assessment
    conductRating   String   // EXCELLENT | GOOD | SATISFACTORY | NEEDS_IMPROVEMENT
    punctuality     String   // REGULAR | PUNCTUAL | FREQUENT_ABSENTEE
    boardReadiness  String   // ON_TRACK | AT_RISK | BORDERLINE
    isPublished     Boolean  @default(false)
    publishedAt     DateTime?
    createdAt       DateTime @default(now())
    updatedAt       DateTime @updatedAt

    @@unique([college_id, student_id, examId])
    @@index([college_id, session_id, examId])
  }
  ```
* **Report Card Generation:**
  - Aggregates subject exam scores from `Result`, attendance percentage from `Attendance`, and qualitative remarks from `StudentReportCardRemark`.
  - Exposes `GET /api/reports/cards/:studentId/:examId/pdf`: generates single-page printable PDF report card via server-exempt `REPORTS` category. Visible in #83 Parent Portal when `isPublished = true`.
