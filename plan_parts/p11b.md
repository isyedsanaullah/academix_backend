#### 11B: Student Leave & Multi-Head Clearance (N24, N29)

##### 1. N24 Student Leave Application Workflow (Standard Tier)
* **Institutional Job:** Self-service online leave submission portal for students/guardians, routed to section class teachers for approval, with automated attendance register synchronization upon approval.
* **Audit-First Model Extension:**
  - The live database already contains `LeaveApplication` with columns `(id, college_id, session_id, student_id, user_id, leaveDate, leaveDateEnd, reason, category, attachmentUrl, status, reviewedBy, reviewedAt, reviewRemarks)`.
  - **Do NOT create a parallel model.** N24 directly leverages and enhances `LeaveApplication`.
* **Additive Schema Enhancements:**
  ```prisma
  // Add to existing LeaveApplication model:
  // campus_id          String?
  // isEmergency        Boolean   @default(false)
  // medicalCertificate String?   // StoredFile.id (category GENERAL / PHOTOS)
  // autoAttendanceDone Boolean   @default(false)
  // appliedByRole      String    @default("STUDENT") // STUDENT | GUARDIAN | TEACHER_ON_BEHALF
  ```
* **Workflow & Attendance Integration:**
  1. Student or Guardian (via #83 PWA) submits leave request: `POST /api/leaves/apply`.
  2. Section class teacher receives in-app alert via `OutboxEvent('LEAVE_APPLICATION_SUBMITTED')`.
  3. **Tiered Layering with N11:**
     - On Standard tier: Class teacher directly approves or rejects (`POST /api/leaves/:id/review`).
     - On Premium tier (when N11 `STUDENT_LEAVE` approval chain is active): Request automatically routes into N11 approval engine (e.g. Teacher → Vice Principal → Principal).
  4. **Automated Attendance Marking:**
     - Upon final approval, an atomic transaction inserts or updates `Attendance` records for every calendar date between `leaveDate` and `COALESCE(leaveDateEnd, leaveDate)`:
       ```sql
       INSERT INTO "Attendance" (id, college_id, session_id, student_id, class, section, date, status, method, markedBy, remarks, "createdAt", "updatedAt")
       VALUES (gen_random_uuid(), $college_id, $session_id, $student_id, $class, $section, $date, 'LEAVE', 'SYSTEM_LEAVE', $reviewedBy, 'Approved Student Leave', NOW(), NOW())
       ON CONFLICT (college_id, session_id, student_id, date)
       DO UPDATE SET status = 'LEAVE', remarks = 'Approved Student Leave', "updatedAt" = NOW();
       ```
     - Sets `autoAttendanceDone = true`.
  5. **Absence Alert Suppression:** `dailyAbsenceAlertWorker` (#86) queries approved `LeaveApplication` rows and skips absent alerts for students on valid approved leaves.

##### 2. N29 Leaving Certificate & No-Dues Clearance (Standard Tier)
* **Institutional Job:** Multi-department digital clearance workflow (Accounts, Library, Labs, Sports, Hostel, Canteen) ensuring no outstanding financial or physical assets remain before issuing an official College Leaving / Character Certificate.
* **Data Models:**
  ```prisma
  model ClearanceHead {
    id           String   @id @default(uuid())
    college_id   String
    campus_id    String?
    name         String   // "Accounts Office", "Central Library", "Physics Lab", "Hostel Warden"
    code         String   // ACCOUNTS | LIBRARY | LAB_PHYSICS | LAB_CHEMISTRY | HOSTEL | SPORTS | CANTEEN
    assignedRole String   // accountant | librarian | teacher | employee
    isMandatory  Boolean  @default(true)
    displayOrder Int      @default(0)
    isActive     Boolean  @default(true)

    @@unique([college_id, code])
    @@index([college_id, isActive])
  }

  model StudentClearanceProcess {
    id             String    @id @default(uuid())
    college_id     String
    campus_id      String?
    student_id     String
    session_id     String
    reason         String    // GRADUATED | MIGRATION | WITHDRAWAL | EXPELLED
    destination    String?   // "Transfer to Government College Lahore"
    status         String    @default("IN_PROGRESS") // IN_PROGRESS | CLEARED | REJECTED | CERTIFICATE_ISSUED
    initiatedById  String
    completedAt    DateTime?
    certificateId  String?   @unique
    createdAt      DateTime  @default(now())
    updatedAt      DateTime  @updatedAt

    departmentItems StudentClearanceItem[]
    @@unique([college_id, student_id, session_id])
    @@index([college_id, status])
  }

  model StudentClearanceItem {
    id           String    @id @default(uuid())
    processId    String
    headId       String
    status       String    @default("PENDING") // PENDING | CLEARED | DUES_OUTSTANDING
    duesAmountPkr Int      @default(0)
    remarks      String?
    clearedById  String?
    clearedAt    DateTime?

    process      StudentClearanceProcess @relation(fields: [processId], references: [id], onDelete: Cascade)
    head         ClearanceHead           @relation(fields: [headId], references: [id])
    @@unique([processId, headId])
  }

  model LeavingCertificateRecord {
    id                String   @id @default(uuid())
    college_id        String
    campus_id         String?
    student_id        String
    certificateNumber String   // SLC-YYYY-XXXXX (gap-free sequence)
    characterRating   String   // EXEMPLARY | VERY_GOOD | SATISFACTORY
    conductRemarks    String?
    admissionDate     DateTime @db.Date
    leavingDate       DateTime @db.Date
    reasonForLeaving  String
    qrVerificationHash String  @unique // SHA-256 for public tamper-proof verification
    fileKey           String   // Generated PDF in category REPORTS (server-exempt)
    issuedById        String
    issuedAt          DateTime @default(now())

    process           StudentClearanceProcess?
    @@unique([college_id, certificateNumber])
    @@index([college_id, student_id])
  }
  ```
* **Business Invariants:**
  1. **Configurable Department Heads:** Does not assume fixed modules (e.g. if Library N35 is not subscribed, the Library clearance head can be deactivated or assigned to general administration).
  2. **Automated Accounts Check:** When Accounts department opens clearance, the system dynamically queries `Fee` and `StudentFee` for open balances; if unpaid dues exist, sets `duesAmountPkr = totalUnpaid` and blocks clearance.
  3. **Certificate Issue Lock:** `LeavingCertificateRecord` can be minted only when `COUNT(departmentItems WHERE isMandatory = true AND status != 'CLEARED') === 0`.
  4. **Post-Issuance Status Transition:** Once certificate is issued, `Student.status` automatically updates to `'transferred'` or `'graduated'`, freeing up student capacity for the college.
