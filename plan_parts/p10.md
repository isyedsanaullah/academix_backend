#### 10.1 Campus model (decided here, once)
**Audit:** no `Campus` model and no `campus_id` exist anywhere. `quotaGate('campuses')`, `limits.maxCampuses` and the `CAMPUS` add-on exist but count nothing today.

| Option | Verdict |
|:---|:---|
| A. Tenant-per-campus (`CampusGroup`) | **Rejected.** Pooled quotas need cross-tenant locking; transfers need ID remapping for classes, sections, ledgers and files. |
| **B. Campuses inside one tenant** | **Chosen.** Matches "campuses under one admin"; quotas pool for free because there is one `College` and one `CollegeUsage`. |

**Design:**
* `campus_id` lives on **`Section` and `Class` only**. A student's campus is **derived** (`Student → Section → campus`). Putting it on `Student` as well would duplicate and drift.
* `GroupSeatAllocation.campus_id` was added nullable in 8A; this migration adds its FK and campus-aware seat queries.
```prisma
model Campus {
  id         String   @id @default(uuid())
  college_id String
  name       String
  code       String
  address    String?
  isDefault  Boolean  @default(false)
  isActive   Boolean  @default(true)
  createdAt  DateTime @default(now())
  @@unique([college_id, code])
  @@index([college_id, isActive])
}
```
* **Exactly one default campus** (raw SQL, Prisma cannot express it): `CREATE UNIQUE INDEX "one_default_campus" ON "Campus"(college_id) WHERE "isDefault" = true;`
* **Owner of campus CRUD:** none exists today, so it is **folded into N18** and gated by N18's Premium key. Creating a campus runs in `withQuota(collegeId, 'campuses', 1)` with the `College` row locked `FOR UPDATE`; `maxCampuses` includes the default campus (Starter/Standard are therefore capped at their one default campus).
* **Explicitly out of scope:** campus-scoped roles or permissions, per-campus timetables and room scoping, per-campus fee heads, per-campus storage quota, campus-specific admins. Quotas stay pooled.
* **Migration Definition of Done:**
  - [ ] Create a default "Main Campus" per college; backfill `campus_id` on every `Section` and `Class`.
  - [ ] Verification query proves zero NULLs; add NOT NULL and FKs afterwards.
  - [ ] Partial unique index applied; rollback script written.
  - [ ] Rehearsed on a Neon branch/snapshot before production.
  - [ ] Contract test: student campus derives correctly after a section move.

#### 10A: N15 IP Allow-Listing (Enterprise)

* **Proxy first:** set `trust proxy` to the real hop count (Render and Cloudflare) and read the client IP only from `req.ip`; never parse `X-Forwarded-For` by hand (spoofable). A test sends a forged header and proves it is ignored.
* **Validation:** IPv4, IPv6, single IP or CIDR via a vetted library; malformed input returns 422.
* **Lock-out protection:** saving a rule set that would block the saver's current IP returns 409 `WOULD_LOCK_OUT_SAVER`.
* **Modes with manual promotion:** `OFF | LOG_ONLY | ENFORCE`. New rule sets start in `LOG_ONLY`. **There is no automatic switch to `ENFORCE`**; an admin promotes it manually after reviewing a summary of "who would have been blocked". (An automatic 7-day promotion could lock out a whole college.)
* **Violation records:** `IpAllowlistViolation` rows are **deduplicated** by `(college_id, userId, ip, day)` (unique) and purged after a retention window by a small worker.
* **Data Models:**
  ```prisma
  model IpAllowlistRule {
    id         String   @id @default(uuid())
    college_id String
    campus_id  String?  // Optional branch-office IP restriction
    label      String   // "Main Accounts Office", "Gulberg Sub-Office"
    cidr       String   // CIDR or single IP
    isActive   Boolean  @default(true)
    createdBy  String
    createdAt  DateTime @default(now())

    @@index([college_id, isActive])
  }

  model IpAllowlistViolation {
    id         String   @id @default(uuid())
    college_id String
    campus_id  String?
    userId     String?
    ip         String
    path       String
    mode       String   // LOG_ONLY | ENFORCE
    dayKey     String   // YYYY-MM-DD
    createdAt  DateTime @default(now())

    @@unique([college_id, userId, ip, dayKey])
    @@index([college_id, createdAt(sort: Desc)])
  }
  ```
* **Coverage:** admin, principal, registrar, accountant and any custom role with `isAdminClass`. **Exempt:** teachers and students, **API keys (N06)**, public routes (#50, #73), the guardian portal, device-ingest endpoints, inbound webhook callbacks and Super Admin.
* **Super Admin escape hatch:** governance action `disable-ip-allowlist` (step-up, audited).
* **"Session controls"** is removed from the registry description (it had no design).
* **Definition of Done:**
  - [ ] `trust proxy` configured; forged `X-Forwarded-For` ignored (test).
  - [ ] CIDR/IPv6 validation; saver-lockout refused.
  - [ ] `LOG_ONLY` records without blocking; promotion is manual only.
  - [ ] Violations deduplicated and purged; exemptions listed above tested.
  - [ ] Super Admin disable audited; registry description trimmed.

#### 10C: N16 Data Retention & Legal Hold (Enterprise)

* **First task, a grep audit** (output in `docs/hard-delete-audit.md`): list every hard-delete call site (`.delete(`, `.deleteMany(`, raw `DELETE`) across controllers, workers and scripts. The plan's earlier "four delete paths" (recycle-bin purge, the 7A 30-day file purge, Super Admin purge, college offboarding) is an assumption until that audit confirms it. `assertNoLegalHold` is wired into **every** path the audit finds.
* **Protected entity set and scope mapping:**

| Entity | `ALL_STUDENTS` | `SESSION` | `STUDENT` |
|:---|:---|:---|:---|
| Student record | all | `session_id` | `id` |
| Fee vouchers and payments | all | via voucher `session_id` | `student_id` |
| Attendance | all | `session_id` | `student_id` |
| Exam results | all | `session_id` | `student_id` |
| `StoredFile` linked to those records | follows the owner | follows the owner | follows the owner |

  `AuditLog` is never purgeable by tenants.
* **Who and how:** `admin` or `principal` may place a hold; **placing and releasing both require password re-authentication** (the existing `/auth/step-up`) and a reason. Release records `releasedAt`, `releasedBy`, `releaseReason`; rows are never deleted. A blocked purge returns 403 `LEGAL_HOLD_ACTIVE`; workers skip held items and log the skip.
* **Precedence (stated plainly):** a legal hold **always wins**. Between `RetentionPolicy` and platform windows, the platform windows (recycle-bin and the 7A 30-day purge) are **floors**: a college's `retainDays` may only **lengthen** retention, never shorten it below the floor. An item is purged only when every window has elapsed **and** no hold applies.
* **`RetentionPolicy`** covers `TRASHED_STUDENT` and `STORED_FILE` only. **No `AUDIT_LOG` retention policy and no audit purge job**, which would otherwise be an unhooked delete path.
* **"Record freeze" vs delete-only:** the registry description says "freeze" but the design only blocks deletes. Decision (OD-24): **change the description to "legal hold (delete protection)"**; edits remain possible and audited. (Blocking edits would require an `assertMutable` check across every update path.)
* **Cold-storage archival is cut.**
```prisma
model LegalHold {
  id            String    @id @default(uuid())
  college_id    String
  campus_id     String?   // Pre-wired for campus-specific legal inquiries
  title         String
  reason        String
  scopeType     String    // ALL_STUDENTS | SESSION | STUDENT
  targetId      String?
  placedBy      String
  isActive      Boolean   @default(true)
  releasedAt    DateTime?
  releasedBy    String?
  releaseReason String?
  createdAt     DateTime  @default(now())
  @@index([college_id, isActive])
}
model RetentionPolicy {
  id         String @id @default(uuid())
  college_id String
  campus_id  String?
  entityType String // TRASHED_STUDENT | STORED_FILE
  retainDays Int
  @@unique([college_id, entityType])
}
```
* **Definition of Done:**
  - [ ] Grep audit committed; helper wired into every found delete path with a test per path.
  - [ ] Scope-to-entity mapping implemented as in the table.
  - [ ] Step-up required to place and release; release audit trail.
  - [ ] `retainDays` cannot go below platform floors; hold beats everything.
  - [ ] No audit purge job; registry description updated; no archival code.

#### 10F: N19 Cross-Campus Student Transfer (Enterprise)

* With campuses inside one tenant, a transfer is a **controlled section move**, not a data copy.
* One transaction: lock the student; **validate the destination section belongs to the destination campus** and a compatible class/session; run the 8A seat check under its advisory lock; update `section_id` (and class where it changes); write `StudentCampusTransfer`; leave the fee ledger, files and attendance untouched (their `college_id` is unchanged). Outstanding fees stay attached to the student; there is no `TRANSFERRED_IN` duplication. No quota change.
* **N11 integration:** add the **`CAMPUS_TRANSFER`** workflow type; with an active chain the endpoint returns 202 and the handler performs the move on final approval.
```prisma
model StudentCampusTransfer {
  id            String   @id @default(uuid())
  college_id    String
  student_id    String
  fromSectionId String
  toSectionId   String
  fromCampusId  String
  toCampusId    String
  reason        String?
  transferredBy String
  createdAt     DateTime @default(now())
  @@index([college_id, student_id])
}
```
* **Definition of Done:** destination-section-in-destination-campus validation; seats respected; fee ledger unchanged (asserted); `CAMPUS_TRANSFER` handler registered; cross-tenant 404.
